# 代码实验台：故障处理

先保存课例，再按对应一行处理。版本 1.0.0，Windows x64。

| 现象 | 处理 |
|---|---|
| 网页提示无法连接 | 双击 `start.bat`，保持启动窗口开启；再点网页“重新连接”。网页本身不能启动本机程序 |
| 双击后显示缺依赖 | 优先完整解压附带 runtime 的发布包；源码版按启动窗口给出的命令安装，随后执行 `start.bat --check` |
| 自动开网页失败 | 复制启动窗口中的 `http://127.0.0.1:端口/` 到 Edge；不要关闭启动窗口 |
| 端口 8765 占用 | 若是已有实验台，重复启动会打开已有服务；否则在终端执行 `start.bat --port 8766`，按窗口给出的新地址访问 |
| 编译失败 | 看底部编译信息，点行号修改，再点“重新运行”；标准选 C++11/14 |
| 运行异常 / 死循环 | 点“停止”，修正代码后重新运行；仍无响应时双击 `stop.bat`，然后重新启动 |
| 大数组卡顿 | 将窗口大小调小，不要展开全部；默认只读 50 格，最大窗口 200 格 |
| 标准输入没有反应 | 输入需在开始前一次性填写；当前不支持运行中交互输入 |
| 变量不显示数值 | “尚未初始化”先赋初值；“状态未确认”表示工具无法可靠判断，不应当成 0 |
| 回看中修改不了代码 | 点“回到最新”，停止当前运行，然后编辑 |
| 切回后台页后会话已结束 | 后台心跳暂停可能导致会话回收；点“重新运行” |
| 载入课例失败 | 确认文件为本工具保存的 JSON，`version` 为 1；不要用 C++ 源文件当课例 |
| 中文路径下 GDB 无法启动 | 保留完整 runtime，先执行 `start.bat --check`；源码工具链太旧时换用完整发布包 |

## 清理与恢复

正常下课用 `stop.bat` 或 Ctrl+C，启动窗口会等待请求结束并清理。强制关闭窗口时 Windows 会终止这一入口所属的子进程树；再次启动会回收上次的临时目录。

确认方法：任务管理器“详细信息”中按启动前记录的 PID 检查本次 Python、gdb、g++、cc1plus、学生 main.exe；不要按进程名称结束其它程序。启动器的 `.local/service.json` 记录本次服务 PID，正常停止后自动删除。不要删除正在运行实例的状态文件。

若源文件夹不可写、压缩包未解压或杀毒软件拦截了编译产物，将**完整发布目录**移到有写权限的位置后重新启动。需要立即继续授课时，停止实验台，回到 Dev-C++。
