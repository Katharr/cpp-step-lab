# 三项验收失败的诊断与修复

日期：2026-11-14。诊断前基点：`2459952`。本次通过真实 GCC/GDB 与本机网页复现，并按元素状态、执行区间证据及网页快照契约核对预期。

## 诊断结论

三项失败均来自执行检查点机制落地后未同步的旧验收断言，本次未修改运行时代码。尤其需要纠正此前初步判断：数组整体 `state=ok` 表示数组结构可确认，并不意味着其中元素已经初始化；实测未赋值元素始终为 `uninitialized/null`，网页显示“未赋值”，未复现栈槽垃圾值泄漏。

| 原失败 | 证据与修复 |
| --- | --- |
| 未初始化数组必须整体非 `ok` | 结构和元素的初始化状态独立。改为逐元素验证未赋值状态与 null，并覆盖远端窗口、部分赋值、A→B→A 窗口切换和历史。只有真正赋值的 `a[80]` 可显示 7。 |
| 函数调用每步都必须没有 writes | `g(int &x)` 的函数体实际执行了赋值，本步经过其真实检查点，应记录写入。修正该调用的期望坐标；其他调用仍要求无写入，并新增只读引用与连续同值写入的对照验收。 |
| 已执行无初值声明的 n 应显示“待确认” | 真实声明检查点已证明其未赋值，应为 `uninitialized/null`，显示“未赋值”。新增同时核对 HTTP 快照、DOM 文字、输入与复制的首次确认高亮，以及历史还原。缺少证据时的“待确认”仍由既有状态验收覆盖。 |
