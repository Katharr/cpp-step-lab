# 发布维护

完整准备、构建和交付步骤见[发布说明](../发布/README.md)。

发布入口为 `scripts/release/build.py`，应用资源由 `APPLICATION_FILES` 显式列出。新增或移动 Python 模块、网页模块、样式、课例、契约及当前文档后，必须同步清单；测试、依赖缓存、本机配置和日志不能进入应用文件清单。工具链和离线依赖另从本项目准备的目录复制，保留原有许可证。

构建新目录前先停止服务。对已组装目录可用 `--refresh` 更新应用文件，按旧 manifest 回收退出清单的应用文件并保留 runtime；不能覆盖正在运行的服务。发布清单与 ZIP 必须使用相同文件范围。

验收顺序：

1. `check.py`：纯逻辑、真实 GCC/GDB、HTTP 与发布文件范围。
2. 启动源码服务，执行所有 `test:browser/data/layout/appearance/visual`，停止并确认清理。
3. 构建或刷新便携包，运行 `scripts/release/verify.py` 验证独立环境、中文路径、启停、硬关闭与取消。
4. 启动便携包，执行 `npm run test:delivery` 拦截外网请求，验证单步、数组、历史与课例。
5. 停止便携包并确认所属进程与工作目录清理；需要交付时再生成 ZIP 和 SHA-256。

验收报告与截图位于 `验收输出/`，不能把旧报告当作本次通过依据。中文路径和空格路径均属于支持范围。项目版本读取根目录 VERSION，单纯目录重构不自动提升版本号。
