# 以真实执行区间统一单步展示

2026-11-13 确认设计方向：一个执行步对应相邻暂停点之间的真实执行区间，允许包含多个动作和对应的源码范围，不强行解释为一条已完成语句。代码高亮、变量状态和容器标记应统一关联该区间，以消除各处独立按行号推断执行完成所产生的分歧。

允许访问归因未知：已确认的数值与数值变化正常展示，归因未确认不在教学界面增加提示，也不能因此伪造确定的读写标记；实现和验收仍须区分未知与确定无访问。数值是否可展示仍需独立的初始化与读取证据。

继续以真实 GCC 执行为依据，必要时允许经过验证的插桩，不另写 C++ 解释器。仅有暂停快照无法保证完整恢复区间内的每次读写，因此统一展示一致性与补充观测能力分别设计。

同日确认：循环头保持原源码行高亮，内部区分实际推进阶段；进入函数时按本步证据展示实参访问，函数体内变化当步展示，调用结果在实际完成后展示。确定的同值写入仍显示写入反馈；首次赋值和新增元素提供反馈，但不虚构可比较的旧值。

窗口扩展不推进执行步、不改变本步归因；历史没有采集过的位置显示“未记录”，不从当前进程补造过去的值。因此接受历史观测不完整，避免为每步回看保存整个大数组。

同日确认首轮验收覆盖常见教学代码的多行与同一行多语句写法、循环、数组与 vector/string、输入、普通函数返回、递归和引用修改，不把核心有效初始化场景长期待确认当作可接受结果。正常结束、异常中断、人工停止均保留适当时刻的最后可信状态；异常可安全采集时保留故障现场，不将旧观测冒充退出瞬间的状态。

本轮已落地核心执行区间路径并完成原始循环的真实验收；复杂表达式与特殊作用域仍按[单步同步设计](../单步同步设计.md)的边界处理。
