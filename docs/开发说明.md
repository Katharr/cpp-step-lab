# 开发说明

本项目面向 Windows x64 上的 C++11/14 单文件教学程序，使用真实 GCC/GDB 执行。安装与日常操作见[根目录 README](../README.md)，课堂操作见[老师使用说明](代码实验台-老师使用说明.md)。本文说明当前实现与维护入口。

## 环境与目录

Python 开发环境统一为项目根目录 `.venv`，依赖由 `requirements.txt` 锁定；网页测试依赖由 `package.json` 和 `package-lock.json` 锁定。网页没有构建步骤，课堂运行无需 Node.js。所有资源从本项目读取，脚本以自身位置解析路径。

| 文件或目录 | 当前职责 |
| --- | --- |
| `start.bat`、`stop.bat`、`launch.ps1`、`launch.py` | 环境检查、启动浏览器、本机服务与所属进程的生命周期管理。 |
| `运行器/runner.py` | C++ 编译、子进程运行、输出限额及清理工具。 |
| `运行器/server.py` | 静态资源白名单、HTTP API、独立页面会话、并发控制及会话回收。 |
| `调试器/session.py` | `DebugSession`、GDB 命令串行执行、取消、快照与临时目录管理。 |
| `调试器/mi_transport.py` | 使用 pygdbmi 创建 GDB/MI 管道并保存原始日志；MI 解析由 pygdbmi 完成。 |
| `调试器/gdb_state.py` | 在 GDB 内置 Python 中读取真实调用帧、块、符号和变量。 |
| `调试器/snapshot.py` | tree-sitter-cpp 语法事实、初始化证据、作用域、身份与快照差异。 |
| `调试器/structures.py` | 数组、二维数组、`vector` 与 `string` 的结构化窗口读取。 |
| `调试器/access_trace.py` | 从已观察到的单步及执行前状态识别可确认的格子读写。 |
| `调试器/io_trace.py` | 编译期接入标准流观测，记录输入消费和新增输出。 |
| `web/index.html`、`web/app.js` | 页面结构、控制、历史、课例、变量和容器展示。 |
| `web/site.css`、`web/lab.css`、`web/data-visuals.css`、`web/syntax.js` | 主题、布局、格子高亮与折叠、代码着色。 |
| `课例/` | 可载入的 JSON 教学课例。 |
| `调试器/cases/` | 真实 GCC/GDB 和网页验收共用的 C++ 回归样例。 |
| `docs/` | 当前使用说明、故障处理、开发说明与效果图。 |

工具链优先使用 `runtime/ucrt64`，其次检查 `C:/msys64/ucrt64` 和 PATH。GDB 需要内置 Python；源码开发使用根目录 `.venv`，便携包携带完整 `runtime`。中文项目路径通过 ASCII 临时编译目录和工具链路径适配处理，不把本机工作区路径写入代码或文档。

## 执行与接口

调用链为：网页 → 本机 HTTP 服务 → `DebugSession` → GCC/GDB → 结构化快照 → 网页。服务只监听 `127.0.0.1`，不提供远程执行，也不隔离用户 C++ 程序的系统权限。

| API | 用途 |
| --- | --- |
| `GET /api/health` | 服务与环境状态。 |
| `POST /api/start` | 提交 `sessionId`、`source`、`input`、`standard`，创建新的运行。 |
| `POST /api/command` | 提交 `sessionId`、`runId`、`command`；网页允许 `next`、`step`、`finish`、`stop`。 |
| `POST /api/window` | 提交 `sessionId`、`runId`、`variableId`、`offset`、`limit`，只刷新结构读取窗口。 |
| `POST /api/ping`、`POST /api/close` | 维持或关闭页面会话。 |
| `POST /api/shutdown` | 启动器使用本次服务的关闭凭据停止服务。 |

一个页面使用独立 `sessionId`，每次重新运行使用新的 `runId`。旧运行请求不能推进或停止新运行。同一会话的执行和窗口操作串行；停止可先设置取消标记，打断正在等待的 GDB 命令。当前最多 8 个页面会话，超过 60 秒无心跳的会话会被回收。

`DebugSession` 提供 `start()`、`execute(command, expected_run_id=None)`、`window(run_id, variable_id, offset, limit)`、`request_stop(expected_run_id=None)`、`close()`，支持 `with` 自动清理。编译默认限时 30 秒，连续执行默认限时 30 秒，课堂暂停不计入连续执行时间；输出上限 1 MB，最多 2000 步快照。

## 快照与展示约定

- `line` 是下一条待执行语句，变量值是暂停时已经形成的状态；不能把两者误标为同一步动作。
- `frames` 使用稳定调用实例身份；变量身份同时包含运行、调用实例、声明与作用域，不能只按变量名匹配。递归、遮蔽和全局变量须分别处理。
- `state` 区分 `ok`、`uninitialized`、`unavailable`、`out_of_scope`。无法证明初始化、读取失败或作用域外的 `value` 为 `null`，不展示栈槽垃圾值。确认标准 `cin` 输入时以真实流状态为依据，不额外调用用户程序的方法。
- 数值以字符串传输，64 位整数不经过 JavaScript 浮点转换。`changed` 表示可靠前后值不同，`previousValue` 保留前值；值状态变化单独处理。
- `data` 包含 `kind/shape/lowerBounds/total/offset/limit/hidden/state/note/elements`；元素包含 `index/coordinates/value/state` 及差异信息。展示层使用结构化字段，不解析 GDB 输出文本。
- 数组默认读取 50 个元素，单窗口限制为 1–200。只读取窗口内元素；切换窗口不执行代码、不新增历史，且保留当前步 I/O 增量与差异基线。`vector<bool>`、不兼容的容器布局和三维以上数组应显示限制说明。
- `arrayAccess` 包含来源 `line`、`reads` 和 `writes`，条目以 `variableId` 和 `coordinates` 定位。用执行前状态确定下标，执行后显示已确认的蓝色读取、橙色写入；写入相同数值也标记。函数调用、条件路径、短路、副作用下标等无法可靠确认的情况保守省略，不通过 GDB 求值用户表达式来猜测。
- `output` 保存累计输出，`outputDelta` 保存本步新增输出，`inputTrace` 保存可确认的输入消费位置。UTF-8 字节位置转换为可展示的文本范围；位置未知时不给出猜测高亮。
- 历史使用独立快照，代码、变量、读写标记和 I/O 一起还原。回看不倒退真实程序；继续执行先回到最新状态。历史回看不重复执行动画。
- 重复值折叠只作用于当前窗口中已读取且可靠的连续相同值。读写、变化和关联下标位置必须露出；未知与未读取部分不能折叠成确定值。
- 课例 JSON 的 `version` 当前为 1，保存 `code/input/display` 和展示设置，不保存执行历史或临时进程信息。

初始化证明和读写识别面向教学中常见的可确认语句，不是通用 C++ 数据流分析。支持范围是单线程、未优化的课堂代码；未定义行为、复杂指针和任意库布局不保证可视化结果。

## 开发验收

先按根 README 准备 Python、GCC/GDB 和本项目依赖。在项目根目录运行：

```powershell
# 真实调试、结构、I/O 与 HTTP 回归
& ./.venv/Scripts/python.exe check.py

# 安装锁定的网页测试依赖
npm ci
```

用 `start.bat` 启动服务，再在另一个 PowerShell 窗口运行所需网页验收：

```powershell
npm run test:browser
npm run test:data
npm run test:layout
npm run test:appearance
npm run test:visual
```

`test:visual` 包含格子视觉及真实读写回归。默认使用本机 Edge，不下载浏览器；`CODE_LAB_BROWSER` 可指定 Chromium 浏览器的可执行文件，`CODE_LAB_URL` 可指定服务地址。验收中的文件直开场景仍使用默认 8765 端口。

按改动选择相关检查；修改调试、静态资源或发布路径时，必须执行相关真实 GCC/GDB 与网页验收。测试结束运行 `stop.bat`，确认本次服务、GDB、编译器、学生程序及临时目录均已清理，不按进程名称结束其他程序。历史通过记录不能代替本次验收。

网页截图等测试产物位于 `web/qa/`；交付验收输出位于 `验收输出/`；命令行调试诊断位于 `调试器/artifacts/`。这些输出、`.local/`、虚拟环境、运行时、离线依赖和二进制发布包均不提交到 Git。日志和课例不存放学生、家长等真实身份信息。

## 发布维护

构建流程与命令见[发布说明](../发布/README.md)。发布资源从本项目清单读取，包含运行模块、网页、8 个课例、当前说明与截图；测试脚本保留在源码仓库，不进入便携包。清单和 ZIP 使用同一发布范围，目录中额外添加的本地文件不会随应用打包。`runtime/ucrt64` 和 `wheelhouse` 需要预先准备，不随 Git 克隆提供。

新版本发布前，在新目录验证中文路径、断网、服务启停、单步、数组、历史和课例载入。`verify_delivery.py` 验证发布包独立运行与清理，`npm run test:delivery` 验证断网网页流程。验收后生成 ZIP 与 SHA-256，不覆盖正在使用的发布目录。

Python 依赖沿用其上游许可证，运行时和工具链保留原有许可文件；新增第三方代码或依赖时记录来源、版本、用途及许可证。文档只在本项目维护。
