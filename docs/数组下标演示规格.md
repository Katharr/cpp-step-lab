- 确认日期：2026-11-14。
- 状态：已实现，具体本次验收见 `数组下标演示验收.md`。
- 目标：帮助学生观察下标变量如何随着真实程序执行而移动。
- 本文记录功能设计与验收目标。当前安装、运行与操作以根目录 README 为准。
- 本文仅在项目内维护，不发布到外部 issue tracker、知识库或网站。

> 文中“本次仅保存规格”等表述保留为设计确认时的历史背景；实施与本次真实验收结果见 [数组下标演示验收](数组下标演示验收.md)。

## 问题陈述（Problem Statement）

老师演示数组算法时，学生需要在变量区域读取下标值，再自行对应数组元素，难以直接看出变量随执行步的移动过程。二分查找尤其需要同时观察左边界、右边界和中间位置；多个变量指向同一个元素时，普通单标签容易遮挡或丢失信息。

当前结构化数组展示已有元素、坐标、访问归因、窗口观测、重复值折叠和手动下标关联，但不足以表达多个下标的移动、重合、分离，以及它们与变量区域的对应关系。

本次首要教学目标是展示“程序运行过程中变量如何逐步变化”，并以二分查找中的 `l`、`r`、`mid` 为重点场景。

## 解决方案（Solution）

在一维数组上方绘制带变量名、当前值的彩色标签与箭头，箭头指向对应元素。数组从上到下依次呈现变量标签与箭头、元素值、元素下标。

每个下标变量在一次运行中保持固定颜色；其数组标签、箭头以及变量区域中对应格子的浅色背景和边框使用同色。数组元素现有的读写与实参使用配色继续表达访问归因。

变量变化时，标签与箭头用约 250 毫秒移动到新位置，并保留上一个执行步的淡色标签和短箭头。多个变量指向同一元素时，标签平滑避让、左右错开，空间不足时分层，所有箭头仍指向同一格。快速操作直接跟随最新状态，不排队播放动画。

系统结合源码中的数组访问和变量计算关系自动识别关联下标；老师可以取消错误关联或补选遗漏变量。越界位置如实显示，窗口外位置提供方向提示与点击定位。所有位置与变量格子使用同一份暂停快照，历史回看使用当时记录的数据。

## 用户故事（User Stories）

1. 作为老师，我希望在数组上同时看到多个下标变量的位置，以便讲解二分查找等算法。
2. 作为学生，我希望下标标签显示变量名和当前值，以便对应代码和数组位置。
3. 作为学生，我希望箭头明确指向元素，以便区分变量值、元素值和元素下标。
4. 作为老师，我希望数组按标签、元素值、元素下标的顺序排列，以便课堂投影时快速阅读。
5. 作为老师，我希望系统自动识别数组的下标变量，以便减少演示前的手动设置。
6. 作为老师，我希望自动关联不依赖固定变量名，以便复用到线性查找、双指针等教学代码。
7. 作为老师，我希望取消误识别的变量，以便纠正自动推断。
8. 作为老师，我希望手动补选遗漏的变量，以便在无法完整识别代码语义时继续演示。
9. 作为老师，我希望关联在本次运行中保持稳定，以便变量暂时未出现时不会反复改变展示。
10. 作为学生，我希望不同下标有不同颜色，以便快速区分多个箭头。
11. 作为学生，我希望变量区域中对应格子使用同色标识，以便找到箭头与变量的对应关系。
12. 作为学生，我希望同一变量移动后颜色不变，以便持续跟踪它。
13. 作为学生，我希望同一变量关联多个数组时颜色一致，以便保持认知一致。
14. 作为学生，我希望颜色之外始终显示变量名，以便不只依靠颜色辨认变量。
15. 作为老师，我希望下标标识不覆盖数组读写反馈，以便同时讲解位置与访问行为。
16. 作为学生，我希望变量变化时箭头平滑移动，以便观察移动方向与距离。
17. 作为学生，我希望看到每个变量上一步的淡色位置，以便比较当前值与前一步。
18. 作为老师，我希望轨迹只保留一步，以便避免多轮执行后画面堆满箭头。
19. 作为学生，我希望两个或更多下标重合时标签避让，以便仍能读清每个变量。
20. 作为学生，我希望重合下标各自的箭头都指向同一格，以便理解它们当前值相等。
21. 作为学生，我希望重合变量分开时标签恢复正常排列，以便继续观察独立移动。
22. 作为老师，我希望连续点击单步或播放时画面直接跟随最新状态，以便动画不拖慢课堂操作。
23. 作为学生，我希望箭头只表示暂停点已经形成的真实值，以便不把待执行代码的结果误认为当前状态。
24. 作为老师，我希望回看历史时变量和箭头同步还原，以便复盘同一个执行步。
25. 作为学生，我希望历史步骤中的淡色轨迹对应它在执行顺序上的前一步，以便不把老师的回看操作当作程序执行。
26. 作为学生，我希望看到负下标或末尾之外的真实位置和值，以便理解循环终止和边界变化。
27. 作为学生，我希望未初始化或值未确认的变量不指向任意元素，以便避免把未知值误当成零。
28. 作为老师，我希望大数组的窗口不在多个相距很远的下标之间来回跳动，以便保持讲解画面稳定。
29. 作为学生，我希望窗口外的变量显示左右方向和当前值，以便知道它位于可见区域之外。
30. 作为老师，我希望点击窗口外的下标提示能跳转到对应位置，以便按讲解需要查看数组局部。
31. 作为老师，我希望实际数组访问继续沿用现有自动定位，以便看到正在读取或写入的元素。
32. 作为老师，我希望窗口刷新不推进程序、不产生新的移动轨迹，以便调整观察范围不会改变执行状态。
33. 作为老师，我希望新标识适配现有主题、布局和减少动效设置，以便继续用于投影和窄屏演示。

## 实现决策（Implementation Decisions）

### 已确认的功能与交互

1. 第一版新增能力以一维数组为范围，二维数组的行列箭头另行设计。
2. 支持一个数组同时关联多个下标变量，不绑定 `l`、`r`、`mid` 等名字。
3. 采用自动识别加手动纠正。直接数组访问是关联依据；边界变量还需要结合数组访问与变量计算关系推断。不能仅因为变量名常见或整数值位于数组范围内，就将它认作该数组的下标。
4. 自动推断不承诺完整理解任意 C++ 程序。老师能够补选与取消关联；本次运行中的关联保持稳定，自动刷新不能覆盖老师已经做出的纠正。
5. 标签显示变量名与当前值，例如 `mid = 4`；箭头明确指向数组格子。标签在上，值居中，下标在下。
6. 不同变量使用不同且在本次运行中固定的颜色。同一变量跨数组保持颜色一致；变量身份不能只依赖名称。
7. 标签、箭头与对应变量格子的浅底色及边框使用同色。讨论中的青色、紫色、玫红色是配色示例，最终色值需结合主题与已有访问反馈验证可读性。
8. 多个变量指向同一格时，标签左右错开、必要时分层，箭头仍分别指向同一格；通过平滑靠拢与避让表达重合，分开后恢复布局，不使用弹跳或抖动。
9. 每个变量只保留前一个执行步的淡色标签和短箭头；当前位置使用清晰的实线箭头，不累计多步轨迹。
10. 新位置与变量格子都来自执行步结束暂停点的同一份快照，不提前表现待执行语句的结果。一步可能包含多个动作，不能强行按源码行模拟移动。
11. 正常单步移动时长约 250 毫秒。连续单步或播放时打断旧动画、转向最新状态，不排队补播中间动画。
12. 历史位置使用历史快照中的变量值；淡色轨迹来自该历史步骤在执行顺序上的前一步，不来自用户刚才查看的步骤。
13. 下标小于数组下界或超过有效上界时，在数组相应一侧显示实际值与边界外箭头，不夹到首尾元素，不把越界提示画成指向合法元素的箭头。
14. 变量尚未初始化、值未确认或不可用时，显示相应状态而不画指向元素的箭头；不把未知值当成零。变量离开作用域后也不得沿用旧位置冒充当前值。
15. 大数组以画面稳定为优先，不为了同时展示多个下标而自动在它们之间切换窗口或无限缩小格子。合法下标位于当前窗口之外时，在左右边缘显示方向、变量名和值，点击可定位对应窗口。
16. 越界位置与窗口外合法位置需要区分：前者表达真实越界，后者允许跳到合法目标元素。实际数组访问继续沿用既有自动定位行为。

### 沿用现有架构的约束

以下约束来自现有项目术语、架构与执行区间设计决策，是实现时需遵守的基础，而非已经完成的改动。

1. 继续基于真实 GCC/GDB 执行和变量采集，不另写 C++ 解释器，不为绘制箭头额外执行有副作用的用户表达式。
2. 源码关联分析归于后端源码事实与快照相关模块，网页消费结构化结果，不在浏览器重新解析 C++ 语义。新增快照字段时同步更新数据契约和接口说明；具体字段形状由实现阶段确定，本文不预先冻结。
3. 关联、颜色和历史还原使用稳定变量身份，区分同名遮蔽、递归调用实例与不同运行。新的运行不能混入旧运行的箭头或轨迹。
4. 数组展示与变量展示共享同一套关联颜色信息，经现有前端装配与状态协作，不建立功能模块间的循环依赖。
5. 保留既有读取、写入和实参使用的语义配色；下标标识与访问归因表达不同事实，不得相互覆盖或混淆。
6. 当前箭头指向的元素不得被重复值折叠隐藏。一步轨迹也应保持位置可辨，不得因折叠而错误落到其他元素；具体折叠排布由实现阶段验证。
7. 窗口观测不推进执行步、不增加历史、不改写访问归因和 I/O，也不被当作一次下标移动。保持现有窗口限额，不为箭头读取整个大数组。
8. 历史缺失的位置不以当前进程数据补齐。历史回看只切换展示，不重新执行或重播当步动画；淡色前一步位置是历史状态的一部分。
9. 配合现有减少动效设置；减少动效时仍清楚表达当前位置、重合标签和一步轨迹。浅色、深色主题及窄屏均需保证标签可读、箭头终点明确。
10. 本次范围不承诺为 `vector`、`string` 新增同等的多下标箭头能力；它们现有展示与操作必须继续正常工作。

### 测试入口与原则

交互规格已确认。以下是依据现有项目结构整理的验收建议；本次仅保存文档，未新增测试、运行服务或执行验收，也不将这些建议写成已有通过结论。

- 优先复用现有真实 GCC/GDB 驱动的网页验收入口：通过本机服务载入 C++ 样例、执行调试动作，观察变量格子、数组箭头、窗口和历史的共同表现。以同一条端到端链路作为主要验收边界，不为每个前端辅助函数另建测试接口。
- 检查外部行为：标签内容、目标下标、颜色对应、可见性、执行步与历史一致性、交互是否生效。不要只断言内部函数调用、CSS 类名或直接复制算法实现来计算期望结果。
- 只有端到端失败无法准确定位，或需覆盖复杂源码关联边界时，补充既有源码事实、快照或真实调试集成层的针对性测试，不预设新增公共测试接缝。
- 既有先例包括结构化数组验收、数组访问归因验收、数据视觉验收和布局验收，以及后端真实调试中的结构与执行证据集成验收。

### 核心验收场景

| 场景 | 应观察到的行为 |
| --- | --- |
| 标准二分查找 | 自动关联 `l`、`r`、`mid`；即使边界变量没有直接出现在数组访问表达式中，也能在该重点样例中关联到目标数组。 |
| 改用其他变量名 | 源码关系等价时仍能建立关联，不依赖特定命名。 |
| 干扰整数变量 | 计数器、目标值等仅因数值落在范围内不会全部成为下标；自动推断可人工纠正。 |
| 手动取消与补选 | 修改即时生效，后续单步和窗口刷新不覆盖手动纠正。 |
| 执行后移动 | 执行赋值后的暂停点才出现新位置；标签、变量格子及代码执行结果一致。 |
| 三个不同位置 | 三条箭头目标正确，变量名和值可读，与变量区域颜色一一对应。 |
| 两个或三个变量重合 | 标签不遮挡，必要时分层；箭头终点为同一格；接近、避让与分离过程清晰。 |
| 前一步轨迹 | 仅前一个执行步位置淡化保留；相隔多步的旧痕迹不累积；首次确认不伪造旧值。 |
| 连续单步与播放 | 快速推进后位置对应最新快照，不出现动画队列导致的状态滞后。 |
| 历史前后跳转 | 当前与前一步标记取自相应历史快照，不由回看顺序决定，不补造未记录元素值。 |
| 负下标与右侧越界 | 分别出现在真实边界之外并显示原值，不错误指向首尾元素。 |
| 未初始化与离开作用域 | 不指向零号元素或沿用失效位置；显示对应的未确认或不可用状态。 |
| 多个远距离下标 | 窗口保持稳定；窗口外合法下标有方向提示，点击后定位对应元素。 |
| 窗口刷新 | 不推进程序、不增加历史、不形成新的轨迹、不丢失本步访问归因。 |
| 数组访问与下标并存 | 既有蓝色读取、橙色写入、紫色实参使用反馈仍然可辨，同值写入继续标记。 |
| 重复值折叠 | 当前下标目标可见，轨迹位置可辨，展开与收起不改变真实下标。 |
| 同名变量、递归与重启 | 稳定身份不串联；同一变量跨数组同色，新运行不保留旧箭头或轨迹。 |
| 主题、窄屏与减少动效 | 标签与变量格子可读，无箭头裁切或整页横向溢出，关闭移动动效仍能辨认状态。 |
| 既有结构回归 | 二维数组、`vector`、`string` 的原有展示、窗口和历史功能正常。 |

实现后需运行本次相关的真实 GCC/GDB 与网页验收，结束测试服务并确认所属进程和临时目录已清理；不得引用历史通过记录代替本次验收。
