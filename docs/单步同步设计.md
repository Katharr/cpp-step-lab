# 单步同步设计

本文件记录正在讨论的重构目标；不是当前功能已经实现或验收通过的说明。术语见 [GLOSSARY.md](GLOSSARY.md)，总体选择见 [ADR-0001](adr/0001-execution-interval-and-evidence.md)。

## 已确认的行为

2026-11-13，前三轮讨论确认：

1. **执行步**：以真实暂停区间为准，可包含多个动作。代码允许高亮对应范围，不强行将区间起点解释成完整语句已经完成。
2. **未知归因**：已确认的值和数值变化正常展示，归因未知不增加教学界面提示；没有证据时不伪造确定读写标记。初始化证明独立于数值能否读取。
3. **执行依据**：保持真实 GCC 执行，必要时允许验证插桩，不自行实现 C++ 解释器。
4. **循环头**：保持原源码行展示，内部区分初始化、条件和更新；不增加循环阶段标签，不把同一行所有动作都当作本步已执行。
5. **函数调用**：进入函数后，下一条箭头跟随函数体；调用处可以表示本步推进起点。已确认的实参访问在进入时展示，函数体内变化当步展示，调用结果在实际完成后展示，不提前显示返回值赋值。
6. **变化反馈**：确定的同值写入仍标橙色；首次赋值和新增元素有出现反馈。不存在可靠旧值时，不显示虚构的“旧值→新值”。
7. **窗口与历史**：实时暂停时扩展窗口读取当前值，不推进步骤、不改变本步执行归因。历史未采集的位置显示“未记录”，不读取活进程来伪造历史，也不要求每步保存整个大数组。
8. **首轮支持范围**：普通赋值、分支、嵌套循环及循环头赋值；一维／二维数组、vector、string 的常用访问与修改；输入、普通函数返回、递归、引用参数修改；以上代码的多行写法和同一行多语句，均进入首轮真实 GCC/GDB 与网页验收。有效初始化后的值应可靠展示，已确认的动作与本步同步反馈。复杂指针、自定义类型、多线程另行界定，不承诺完整读写归因。
9. **终止展示**：正常结束保留最后采集到的可信状态，清除下一条箭头。异常中断优先安全采集故障现场，不能采集则保留最后可信状态并说明它属于中断前。人工停止保留最后可信状态，不把停止操作当成执行完成；不把先前数值冒充退出瞬间的数值。

## 拟定的职责与约束

以下是据已确认行为整理的实施方案。本轮已落地“完整执行区间结束后提交状态”的核心路径，并用真实 GCC/GDB 验证原始循环；其余扩展范围仍按下文限制处理。

### 执行观测与归因

- 调试执行负责推进程序、记录暂停位置与调用帧，并采集暂停时能安全读取的状态。源码行和 PC 是定位证据，不独自构成语句完成证明。
- 一个执行归因 module 统一解释本步推进范围、调用进入与返回、完成程度。初始化与访问识别共同消费这份执行解释，不再各自比较前后行号决定动作是否完成。
- 静态源码事实说明可能发生什么；实际执行证据决定哪些动作能归入本步。不能通过忽略短路、循环阶段、未完成调用等差异来扩大“确定”范围。
- 初始化证明、数值变化、首次确认、元素新增与访问归因分别记录。值来源无法证明时继续保护未初始化数据；不能仅为消除“待确认”而放行原始栈值。
- 对外 interface 提供同一步的执行解释和状态结果；复杂推断集中在 implementation，避免要求调用者掌握推断顺序。

### 展示与历史

- 代码、变量、容器和 I/O 使用同一个执行步的结果完成一次展示提交。前端 editor 删除独立的执行完成推断，保留定位和样式职责。
- 执行步与观测时刻有稳定身份。实时窗口读取可增加当前暂停点的观测覆盖，但不修改本步动作事实、I/O 增量和初始化证明。
- 历史保存执行事实及实际采集的数据；重复读取窗口应幂等，不运行执行归因，不通过弹出历史、重新 build、补回字段来模拟刷新。
- 新窗口没有对应的旧值时，不计算虚假的前后差异。结束后可以浏览已保存数据，但不能再读取已退出进程。
- 后端保留访问未知与确定无访问的区别，用于诊断与验收；教学展示不增加归因未知提示。

### 保留的工程约束

- 沿用 start.bat、stop.bat、本项目 .venv、依赖锁和离线运行要求；工具链或依赖若需要调整，应由项目管理并验证发布影响。
- 保留现有课例与用户课例格式、稳定变量身份、调用帧身份、旧请求防覆盖机制和单步控制入口。
- 以本机当前版本实测编译、单步、扩窗和历史回看耗时作为性能基线；方案不得依赖每步遍历整个大数组。实现验收报告需要明确比较结果与尚未解决的性能限制。
- 不通过另写 C++ 解释器、预置所有局部变量为 0、重新执行有副作用的表达式或使用当前值补历史来满足验收。

## 拟定的实施顺序

1. **技术验证**：建立精确复现原始 i、j 问题的真实执行测试，同时覆盖循环头数组更新、多行初始化、普通函数返回及引用修改。检验仅靠现有 GDB 观测可获得什么证据，必要时验证插桩与源码映射；先回答“能否可靠满足核心场景”。
2. **统一执行步**：根据验证结果确定执行解释与观测证据，集中归因逻辑，补充快照约定及整步测试，再接入各展示位置。
3. **分离窗口与终止观测**：窗口扩展退出执行推断；正常结束、异常和人工停止采用已确认的保留规则。
4. **迁移和清理**：迁移现有教学场景并删除旧的重复推断与补偿流程；运行完整相关验收，停止测试服务，核查所属进程和临时目录。

技术验证可以揭示观测路线不可行；此时应记录证据并重新选择路线，不把失败场景改成“允许未知”以宣称首轮范围已经完成。插桩须验证求值次数、短路、引用、函数调用和源码位置映射，不能假设插入语句不影响程序语义。

## 验收矩阵

| 场景 | 必须检验的行为 |
| --- | --- |
| 原始嵌套 for 示例 | 初始化后 i、j 可靠显示；结束前均为 5，输出为 2#6#12#20#25。 |
| 循环头更新数组 | 数值变化和可确认的访问关联同一步；不把初始化、条件与更新混算。 |
| 零次循环、break、continue、回跳 | 不对未执行动作产生确认或读写反馈。 |
| 多行／同一行多语句 | 允许一个区间覆盖多个动作，格式差异不导致有效初始化值一直待确认。 |
| 一维／二维数组 | 下标取相应求值时刻，读写坐标与本步一致。 |
| vector、string 常用修改 | 元素新增、值变化和访问分别验证，不伪造旧值。 |
| 普通函数返回及 next / step / finish | 实参、函数体与返回后赋值按真实完成时刻反馈；操作方式不导致结果变量失去有效证明。 |
| 递归和引用修改 | 调用实例、变量身份与被引用对象正确关联；不将未初始化对象因传引用而判为已初始化。 |
| 输入成功、输入失败 | 仅确认实际获得有效值的对象。 |
| 同值写入、首次确认 | 有对应反馈，但不产生虚构的数值差异与旧值。 |
| 短路、条件分支与副作用 | 不重复求值，不伪造未执行路径的访问。 |
| 扩窗 A→B→A | 不增加执行步，不改变本步归因与 I/O；旧值未采集时不伪造差异。 |
| 历史未采集元素 | 显示未记录，不从活进程填补历史。 |
| 正常结束、异常、停止 | 保留合适时刻的可信状态，终止后没有下一条箭头，不伪装完成。 |
| 连续点击、播放、停止与历史回看 | 同步提交同一步，各处高亮不被旧请求或动画覆盖。 |

除纯逻辑测试外，关键场景必须经过真实 GCC/GDB 与网页验收，覆盖 C++11/14；源代码、观测证据和页面结果形成可核对的同一条执行记录。

## 本轮落地边界

核心路径已经确认：检查点只在实际执行区间完成后提交可信状态，故障和停止沿用最后可信状态，历史窗口不读取当前值。条件声明等容易破坏源码作用域的复杂形式暂不插桩；复杂指针、自定义类型和多线程仍不在首轮承诺内。通用插桩的完整性能和所有复杂表达式的归因仍需单独验证。

## 本次审查证据

- 原用户代码：先声明 i、j，在 for 初始化中赋值；真实 GCC/GDB 可读到结束前二者均为 5，但现有初始化规则未确认值。
- 真实 GCC/GDB 探针：for 更新部分执行数组元素自增，值从 0 变为 1、2，数值差异被记录，但容器访问记录为空。
- 同一探针：同值数组赋值没有数值差异，但能生成读取和写入记录，说明数值差异与写入必须分开。
- 窗口刷新当前通过回退、重建和恢复字段保留本步信息；这是结构耦合事实，本次未据此声称已经复现窗口错误值。
- 本次静态核对：结束状态不采集变量，结束快照会将上一暂停点变量清空并标为离开作用域；先前历史仍保存原值。信号异常同样没有先采集故障现场，需另行定义终止展示。
- 本次静态核对：已有编译期 I/O 观测，不存在通用变量读写插桩或源码变换映射；多行初始化和普通自定义函数返回的证明仍受保守规则限制。它们不是已经完成的支持能力。

以上用于记录设计依据；本轮核心验收已由真实 GCC/GDB、相关集成测试和网页测试覆盖。
